# Real Windows acceptance plan (NOT executed in kit creation session)

Run these on a Windows 10/11 x64 PC with 10+ GB of free writable disk space and a backup of any existing application data. Install/upgrade tests must use a **separate disposable PortableApps directory** to avoid damaging a real application. Do not run invasive host scans or delete registry entries. Record `MANUAL-WINDOWS-TESTED` only for tests you actually perform.

1. **Fresh ZIP and correct launcher.** Verify SHA256SUMS using `Get-FileHash` and compare the hash from your builder release. Extract into `C:\Portable Test 字符\WatermarkRemoverAIPortable` (or another writable location). Check `WatermarkRemoverAIPortable.exe` is a genuine EXE, all `App/WatermarkRemoverAI/python` files exist and `Data` is initially empty. Launch via the root EXE. Check the UI opens.
2. **Real settings.** Change the theme/language, close the window, wait for all application/worker processes to exit, and relaunch. Confirm settings persisted and `Data/ui.yml` and `Data/desktop.log` exist. Confirm no `App/WatermarkRemoverAI/data` is created.
3. **Model downloader.** In Models > Download / Retry, trigger first download, an intentional network failure, and retry. Check files under `Data/models/torch` and `Data/models/huggingface`. Check the pinned models validate before use. Inspect nested empty folders after aborted downloads, and verify they remain on portable drive when moving the package.
4. **Image/video.** Use only test inputs you own and are entitled to edit. Try a small test image, preview, image processing, cancellation, and bad input. Test video; if you need audio, independently make FFmpeg available on PATH, verify audio, then test without it and observe the documented limitation.
5. **Process lifecycle.** Close during idle, model download, processing and cancellation. Examine Task Manager for remaining `WatermarkRemover-AI.exe`, `python.exe`, `pythonw.exe`, Qt helpers and FFmpeg processes specifically attributable to this instance. Do not kill unrelated installed-application processes.
6. **Installed-app coexistence.** If you have a separate upstream installed/source copy, back up its own profile. Take pre/post snapshots of only known application-specific locations (`%LOCALAPPDATA%\WatermarkRemover-AI`, `%APPDATA%\WatermarkRemover-AI`), plus evidence-confirmed Qt cache folders. Verify the root PortableApps launch did not overwrite any existing host profile. Do not remove ambiguous files.
7. **Shell integration.** Observe Start Menu, Desktop, Startup, HKCU software registration, notification functionality, taskbar pinning and jump lists before, during and after running. Do not classify Windows-generated recent-history caches as portable-app-owned data without evidence. This app has no verified source-level toast activation registration in the inspected build.
8. **Drive/folder relocation.** Exit fully, copy or move the whole folder including `Data` to a drive with a different letter and Unicode/spaces path; launch again, verify selected model caches/settings persist. Re-select media paths if previous absolute paths are stale.
9. **Shared installer fresh install.** On a disposable test location, run the `.paf.exe` normally and choose the empty test location. Confirm `App`, `Other`, root EXE, `Data` and metadata. No admin rights or setup steps should be necessary. Note that this is an independent NSIS installer rather than the official PortableApps.com Installer.
10. **Installer upgrade/Data preservation.** Create test files and a nested empty directory inside `Data`, then run a second installer of the same application identity from a newer supported version. Verify settings, logs, model files and completely empty directories survive. Check obsolete binary cleanup in `App`; do not upgrade over a running application.
11. **Rollback/failure.** Copy the entire disposable installed tree first. Test locked-program rejection, wrong AppID rejection, and if safely possible an interrupted installer in a throwaway test machine. Check `.__UPB_Backup`/`.__UPB_Stage` are not silently destroyed after errors. Restore from the disposable backup, including the full `Data` folder. **Never inject test errors into a real user install.**
12. **Repeat and compare.** Relaunch multiple times, watch for accumulative app-owned host writes and stranded background workers. Report remaining limitations and whether results were source-inspected, static, CI runtime, or manually Windows tested.

### TraceGuard and ShellGuard threshold

Do **not** add automatic removal just because a directory has a similar name to the application. If testing shows an unavoidable specific application-owned external folder (including fully empty directory trees), first establish an exact path/creator and pre-existing data behavior. Prefer a supported source/framework profile setting. If this is impossible, implement a very narrow transactional migration with manifests, fingerprint checks, backup, conflict handling, symlink/lock protection, and independent manual tests; never harvest shared `%LOCALAPPDATA%` or Windows shell branches.

### Optional command-line diagnostic

From the extracted package, use PowerShell `& '.\WatermarkRemoverAIPortable.exe' '--check'` to trigger the actual upstream Qt desktop diagnostic through the community launcher. It verifies the local UI/bridge but does not download models or process real media.
